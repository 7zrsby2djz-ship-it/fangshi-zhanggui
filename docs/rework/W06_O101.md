## 實裝與理由

- 第二天報紙須按「讀報」才取得雨訊；第三天市場須實讀韓九這趟出發／四包需求，以及鐵師傅當場四份布繩／短試，才有消息與本次現場供貨。未看供貨不會顯示「已看短試」。
- 兩條消息齊全可見卡片；現場有效、資金至少 24 才能一鍵備貨。專用四份放在商案記錄，沒有耗用碧水符、複製普通庫存或增加額外時段。離場、過日或再次進場都不能沿用上次採買來源。
- 第四天首次顧店先接韓九，實際逐包試布後才可收 36、交付四份。香菇一直屬貨主，沒有變成庫房或身家。第六天早上送達持久回報；實讀才學得回流消息。讀過仍能再開全文，沒有重複款、貨、收據或獎金；延期閱讀顯示原到達日期。
- 未備貨過期不發貨；已備貨未成交／拒售則一次轉回普通四份，現金退款 0，參考總估值 16。轉回後按普通市價及剩餘數量估值；賣掉一份不會仍算整批 16。
- 新局所有狀態都禁用舊 d13 收香入口，排除舊錯過計數；月底另列韓九成交／未承接／轉貨的事實，不借用 d13 真相或判決。d12 延至第五天，事件仍絕對第六天，臺詞及封口消息的 hot／expire 同步；一般白七娘查證仍付 5、占一格。其他壽命、規費、事件答案及評等公式沒有更改。
- `nextShopDeal` 從純 `prio` 改成先期限較早、再 `prio`、最後 ID。O101 第四天先接後，d11 當天截止，因此第二次顧店會穩定接到 d11；第五天 d12 截止，仍可排到。這項排程會改變其他同日可見舊客的先後，沒有改其答案、報價或時段費用；不是只調 d12 的紙上日期。
- 契約的供貨 `checkedFlag` 以商案 `source` 快照及 `place.session` 相符判定實作。實讀來源才建立快照；進場遞增 `visitSeq`，離場或不同日期／session 不可備貨。沒有用 renderer 或永久旗標補出未觀察的供貨。
- 通用抵費、散客直接出售、鐵師傅／回春堂／市場擺攤、委託配方與一般夜間耗材，實際扣貨入口保護唯一故事物、受託及證物。配方混放時只吃可用普通貨。明確敘事的歸還／移交、既定犯罪後果仍沿原 `takeQty`／事件入口，避免把故事流程一併封死。受託／外物不列玩家身家、庫存估值及月末庫存小計；自有不可出售故事物維持既有估值政策。

## 限制與待驗

這輪新舊引擎驗收使用 Node VM 與最小 DOM／localStorage 介面替身，執行完整核心函式，沒有以灌旗標取代正常 O101 流程。人工壞檔、保護及跨月探針已在測試註記，沒有稱為真人玩法。

未測真實 Browser 版面、觸控、iframe 執行／檔案 URL localStorage 共用及下載行為；目前執行環境無可用 Chromium。程式不依賴不同 file URL 共用保存空間；若另一檔原進度不可見，提供明確 JSON 匯出／匯入入口，但各瀏覽器同源 `srcdoc` 與 `file:` 儲存實際行為仍待實機驗收。沒有完成市場所有互動、所有舊犯罪支線、兩月平衡／全部公制移植或大規模可達性證明。O201–O204 未加入資料與執行分支。

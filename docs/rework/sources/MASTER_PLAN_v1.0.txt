## 02 本次重構要達成的結果

【確定】前兩個月應讓玩家經歷：普通交易與人情 → 消息拼成商機 → 願意為自己的判斷押錢 → 等待出門的人 → 收到新貨、損失或故事 → 開始注意百年前的碎片。

【建議】完成標準：
1. 第一月能完整體驗一個教學商機，包含至少兩個消息線頭、一次備貨決定、成交與後續回流。
2. 第二月有四個核心商機，另留兩個條件式商機的擴充位置；兩至三位求助者可同時是商機顧客，不另疊一批任務。
3. 願意打探、判斷與備貨的玩家，收入逐漸來自消息商案。拒絕商案的玩家仍能經營，不能被唯一解軟鎖。
4. 讀者能分辨主要人物的個性；許衡熟悉生活常識，推理只使用他已取得的資訊。
5. 前兩月結束時，玩家想知道下一位探索者是否回來、帶回什麼，也開始注意 2029/12/31；不能已經知道末日原因。

本輪範圍包含既有前兩月文本、必要的新消息與商機、存檔相容性，以及必要的圖示與稱呼調整。第三月、跨海可玩地圖、完整境界系統、所有結局動畫、大量新美術與長篇世界觀動畫留給後續階段。前兩月可以埋下結局所需的行動紀錄，不能順勢把全部終局也做完。

小說原型先驗證故事，通過後才拆入遊戲。單篇原型代表一條可發生的路徑；其他玩家選擇由分支規格承接，不為每條路都另寫一部小說。

製作順序採「故事先於物品」：先有人的目的、生活或探索事件，物件在其中自然出現，玩家才逐步知道它、記得它，再決定是否成為交易品、持有物、情報線索或商機材料。第 06 節是舊內容改造盤點，第 09 節是玩法驗證槽位，都不要求寫手把清單逐件塞進故事。每輪只推進下一小段；需要什麼，再登記什麼。

## 04 世界觀與人物底線

### 04.1 必須一致的世界

【確定】舞台是 2029 年末大災變後約一百年的臺灣高山聚落。不是中國古代；也不是臺灣成為全球唯一倖存地。其他高山、高原與山島仍有人類，但前兩月不需要列出完整政治地圖。

臺灣中央山地有不正常隆升，低地大量淹沒。玉山是重要意象，最終高度、災變地理機制都未定。「臺灣向上長，未知世界向下延伸」是長期空間意象，不能由此杜撰精確海拔或宣稱所有異常都有同一入口。

全球海洋局部出現不連續的深度與落差；海水與船可能墜入異常區，海水持續流入但海平面未因此下降。近岸捕魚和局部航行仍可能存在，穩定遠洋船運則受到根本破壞。人類知道怎麼造船，問題在海本身與供應鏈。

修行源自災後人體與異常環境的適應。礦物、植物、動物也受影響。吐納、靈根、靈石等詞可以保留為後來的文化稱呼，不得寫成自古存在的客觀仙人史。具體科學名稱只是候選，不能反過來裝作已證實機制。

境界除了戰鬥，還影響可到達的地理。普通人生活於安全聚落；較低階修行者可做近域探索；金丹能承受更強的深度異常並帶回陌生寶物；元嬰有跨海、跨區域移動的可能。因此元嬰來店應是重大事件，不是隨機散客。前兩月透過人、貨與消息看見遠方，不開跨海地圖，也不立即教完所有境界。

舊世界知識沒有全部消失。居民可能知道臺灣、日本、臺中、南投、嘉義、玉山、高鐵、捷運、超商、手機、晶片、AI、台積電與悠遊卡。認識設備不等於能重建製造供應鏈；職業與教育造成知識差異，不能把全體居民寫笨。

### 04.2 2029 年末與刻意保留的未知

【確定】在本作虛構歷史裡，2029 年底 AI 接近能取代 99% 人類工作的臨界點；這是作品設定，不是對現實未來的預測。裁員、公司無人化、失業政策、教育與放款變化，呈現當時的社會壓力。真正災變緊接而來，時間集中在 2029/12/31 前後。

不得使用「AI 開智了」「祂睜開眼」「覺醒後宣戰」當預設答案。AI 是原因、提前發現者、阻止者，或只是同日存在的社會背景，都保持可能。人類實驗、自然現象、外界文明、高維空間等同樣只是可能解釋。

以下不補官方答案：水流去哪、海面為何不降、深度另一端、災變和深度是否同源、AI 是否有意識、台灣隆升完整機制、元嬰跨海物理機制、靈石全部來源、境界全套數值、全球倖存地清單，以及正式深度區和冒險包名稱。

【建議】局部事實必須清楚：這批貨是否受潮、誰真的說過哪句話、錢何時付、誰帶走物品，須有固定紀錄。世界大謎可以開放；玩家眼前的交易不能事後換答案。

### 04.3 許衡

【確定】他是在地生活的人。不能為了向玩家解說，忽然不懂本地常識；不能擅加穿越、奪舍或失憶來補洞。他的長處是記得別人講過的話，並把時间、需求、價格與行動連起來。這不等於看穿所有人，也不等於知道玩家尚未取得的資訊。

【現況】舊版寫他 31 歲、有父親店鋪與家庭舊案。這些可供沿用，但新世界的身世解釋需列入決策。日常故事不必每一幕都連回父母、長生典或末日。

他的知識分四格：在地常識／店務專長／本幕才取得的情報／至今不知道的事。寫手每幕先確認後兩格。玩家不知道的常識，可透過許衡做事、價格和別人的反應看懂，不必讓他問蠢問題。

### 04.4 文風與場所

【確定】使用自然的繁體中文與臺灣生活語感。居民會裝熟、酸人、顧面子、算利益、嫉妒、講八卦，也會有真誠與害怕。粗口按角色使用，不把每人都寫成同一張嘴。

「許衡道」「阿成道」等說話者標示可以自然使用；多人對話換人時尤其要清楚。關鍵情緒要有可見動作、表情或停頓。動作必須反映目的、壓力或關係，不能每句都補「笑了笑」「看了一眼」。NPC 的沉默也要有當下理由。

執事堂對外名稱採警察局／派出所方向；【建議】聚落現場先稱「派出所」，較大上級機關才稱警察局。這個用詞選擇不自動導入今天臺灣整套行政法制。周正、陸執法各自的權限仍須重新說清。

丹坊依功能改為藥行、藥店或診所；洞府區可改住家區、後山石屋；坊市可保留正式名稱，居民說市場或老街。避免大量「客官、在下、閣下、此物、莫非、掌事、覆命」；特殊角色刻意古腔需有理由，不全面禁止個人語癖。

專業藥行不靠分不清常見藥草製造劇情。品質差異主要來自散客、市集、混批、保存與故意造假；學徒不熟某種新異常材料可以成立，但要有能力邊界。小石頭先碰到真貨、後來自己被騙的關係骨架值得保留。

### 04.5 特殊物件與證據

【確定】狐尾燈是特殊的一件，不能被當成量產商案材料。重構須明確把許衡那盞特殊燈與攤位普通燈分開；舊文「一排排同款特殊燈」「每年再買一盞」若指同能力物件，必須改寫。這不禁止世界上存在其他普通燈。

【現況】正常玩法中領燈完成記錄會跨月保留，不能僅因 repeatable 就說現有程式會讓玩家無限領燈。現行功能是協助察覺小動作，不是直接顯示真假判決。重構保留玩家判斷空間。

歷史碎片先是一件與人有關的物品，再是證據。跨年行動電源、聘僱終止通知、觀測浮標、員工證都是原交接的示例，不是必須逐件實裝的清單。日期應從不同來源自然重現，不能每件新貨都剛好印上完整日期。

【建議】一件物品有日文，只能證明它與日文使用者或工藝有關，不能單靠這點證明災後日本仍有人。若要讓玩家確認，至少再有近期製造／修補痕跡、可對照的現在日期，或可信的近期往返證詞。角色可以猜，旁白不能把猜測升格為事實。

異界貨可以像玻璃又像植物、像金屬又像器官，外形明顯不同於臺灣日常；但線條、筆觸、色盤、尺寸與介面仍遵循同一美術系統。先讓玩家好奇用途，不用 SSR 標籤代替想像。

## 06 舊內容如何留用與替換

### 06.1 三種處理

保留骨架：交易中的資訊差、人物互相欠人情、消息外洩後果、跨月關係、物件歸屬、誠實者被誤解，以及做生意的選擇代價。

重新寫作：台詞、敘述、稱呼、場所、制度外觀、物品名字、生活細節、古風身分與裝束。句子沒有保留義務。新名稱只有在符合來源、用途、供應與人物生活時才採用。

另做決策：典壽、舊家族案的紀年、宗門與地方權力、超大空間器具，以及異常能力的上限。凡改動會使既有線索失效，必須連同線索、選項、後果一起重寫，不能只換一個名詞。

## 07 讓小說持續穩定的寫作方法

### 07.1 每次只承諾一幕

【建議】初期每幕正文 600 至 900 個中文字，最多 1,200 字；這是試行上限，依偉銓閱讀感受調整，不是品質保證。每幕一個主要目的、一個衝突、一個可見的局部結果。兩至三位主要說話者，至多帶進一項新的世界規律或特殊物件。

一幕結束先停止正文生成，完成自檢與狀態紀錄。單幕任務不自動續第二幕；已授權的批次任務則逐幕處理、逐幕檢查，不連寫整章後才補檢查。人物卡、場景卡與檢查表放在正文之外，不把工作說明混進小說。首幕讓偉銓看具體稿件確認口吻，之後沿同一標準分幕驗收；不要求每句、每個名字都來回請示。

### 07.2 開寫前的場景卡

每幕必填：場景 ID 與版本；月／可玩日／時段；地點與天氣；進場與離場人物；上一幕留下的狀態；人物各自想得到什麼；已知與未知；本幕貨物及所有者；2 至 4 個故事節點；玩家可選什麼；本幕結束時改變什麼；禁止提前透露什麼。

若缺資料，先查狀態表。只有不影響後續的杯子、衣角、小動作等細節可自行補足。會改變人物能力、關係、世界規律或線索答案的新增內容，先列提案，不邊寫邊升格為正式設定。

### 07.3 寫後留下的狀態差異

至少記六項：誰知道了哪件事；誰持有哪件物品；誰欠誰什麼；當下資金／承諾的變動；人物在哪裡；尚未回收的伏筆與最早可回收時間。引用的消息來源也要記入。

新一輪寫手讀「固定規範、角色卡、本幕卡、上一幕全文、累積狀態差異」，不必反覆把整個 repo 和兩月長篇塞進同一段提示。跨三幕再做一次總檢查，確認線索、日期、人物情緒和物品沒有漂移。

### 07.4 八條退件標準

1. 許衡用旁觀玩家的無知代替自己的在地常識，或突然穿越／失憶。
2. 角色說出不知道、無法得知，或在本路線從未被告知的事。
3. 人物說一句漂亮話，卻看不出他此刻為什麼要講、想讓對方做什麼。
4. 全篇只剩一問一答；或硬塞表情，反而人人同樣皺眉、冷笑、嘆氣。
5. 後半段另開大支線，沒有完成本幕原先的生意、衝突或情緒。
6. 新物件臨時多出能力、取得方式或數量；唯一物品變成普通消耗品。
7. 旁白替末日定罪，或把角色推測寫成客觀定論。
8. 用一個眼神或完整口供直接送答案，破壞公平的推理與選擇。

每次退件指出具體段落與破壞的規則，優先局部修復。不因後段兩句失控就全面重寫前面已通過的內容。首幕合格稿另標為文風樣本，後續沿用其節奏與人物表現，不重複它的句型。

### 07.5 台詞是否站得住的最小檢查

對每句關鍵台詞問三件事：他回應的是前面哪件事；他想改變對方什麼行動；說完後誰的處境改變了？例如「現在知道不知道有多煩了吧」若缺少先前被敷衍的具體經歷與當下反擊目的，就刪除或重寫，不另加一段說教替它找藉口。

推理規則沿用 README 的方向：非誠實交易原則上 3 至 5 條線索，分散至少 3 種管道；單一線索不定案，各有無辜解釋；誠實交易也容納 1 至 2 個表面可疑點。故事對話、物品與驗貨資訊可以互相補足，不必在每一幕機械塞滿全部管道。

## 09 消息商機的內容設計

### 09.1 玩家實際會看到什麼

【確定】兩至三則已取得消息湊起來時，顯示「許衡想到了一樁生意」。卡片列出來源與許衡怎麼把它們連起來，並提供「備貨，投入 X 靈石」與「不做／先不做」。常規物資由系統依已知可用來源配好，不拖曳，不逐件湊配方。

顧客付的加價來自適配、風險判斷、打包、省下查找時間與情報服務；不能只是同一批貨憑空漲價。玩家要能看懂預計投入、可知的風險、可能需求窗口及未成交貨物怎麼處理。卡片的語氣可以是「可能用得上」，不能用作者知道的 hidden truth 宣布「一定賺」。

「不做」不扣資源；「先不做」保留到已公布期限。若介面只保留一個拒絕選項，就明示是否仍可回頭。過期與猜錯分開：沒顧店、消息已過時、消息是假的、貨本身不合格，各要有不同可理解的結果。

顧客買走後，收入已發生，探索結果還沒完成。幾天後回來的人、口信或退回的物品，帶回另一層結果。成功不等於每次救命；可能只是沒有出事、少走冤枉路、保住一批貨。損失不能只靠玩家事先無從得知的隨機懲罰。

### 09.2 第一個可玩切片 O101

【建議】題材為「短程運送的防潮準備」，正式名稱與實物待小說確認。可借既有雨訊、保存問題和區域運送者的功能，不預設沿用避水符。

- M1D2 可得線頭 A：部分倉庫進水的傳聞，原始依據 n_rain。建議在玩家實際看見晨報後記為新 intel i_opp_rain；仍標成傳聞，不當親眼驗證。現行 beginDay 只設定 todayNews，尚未自動建立這則 intel，W06 必須補接取得接口。
- M1D3 可得線頭 B：運送隊 M1D4 要走一段容易讓貨受潮的路，新對話必須交代消息來源及預計出發。建議使用 han 的功能，但改成在地山路運送，不預設駝隊。
- 同次市集行動可確認合格常規來源，建議記為新旗標 opp101_source_checked，W04 指定取得對話、有效期與供應入口；受潮商品的觀察可作額外查證，不要求玩家先受騙才有資格做教學。線頭已齊但尚無可用來源時，卡片可提示「先確認供貨」，不得直接備貨扣款。
- 湊齊指定的已知線頭後亮卡，玩家一鍵備貨。顧客於 M1D4 的一次顧店行動出現，M1D6 以晨間卡與短段落回報。
- 這筆替代或改造原有 d13 固定收購的位置；不同時又發一份相同顧客與同一批貨的完整收入。
- 若拒絕或來不及成交，常規貨保留可辨識的去向；建議期限後按事先顯示的規則折回普通庫存。不能默默消失。
- 必要回流只安排在前兩月可玩的窗口內。跨月機制另用測試情境驗證，不為測試強迫首個教學跨月。

用於工程驗收的試算值：投入 24、成交收入 36，商案毛利 12；若為此多花 3 查證，淨貢獻為 9。若未成交並轉回估值 16 的普通貨，當下現金流為 -24，資產價值減少 8；後續賣貨收入另算，不能轉貨時又退款。若正式設計改採退供應商現金 16，才是淨現金損失 8，且不得同時保留那批貨。這些是測試參數，不是已平衡售價，也不保證後續每案獲利率相同。

正式試算需同時計入購貨、查證、退款、未售存貨、時間機會成本；不能把稀有遺物的故事價值當現金收益灌入報表。備貨採專用記錄，不先扣玩家的故事物品。

| O201 核心 | 礦區維修有規格和交期 | m218／m213 的採購功能，擇一整合 | 工作者回報使用結果與新通道消息；錯估規格有明確退貨 |
| O202 核心 | 出行者預算有限且有身體限制 | m219 的出行用藥需求，可由採集者接手 | 求助者選兩至三方案；結果反映已知條件，不玩猜作者 |
| O203 核心 | 返程運送與材料保存 | han、常規容器與修理功能 | 來源新鮮度與品質影響回流；可能帶一件舊世物品 |
| O204 核心 | 淺層探索需要特殊但已知的準備 | 新探索者或現有成年人 | 一項異常、一件新貨；不可突然出現元嬰旅遊團 |
| O205 選配 | 已建立信任者先透露需求 | 既有關係與口碑 | 未建立關係則不出現，並不阻斷主要經營 |

四個核心是可供發現的內容量，不要求每局全做完。每局能合理完成兩至三案，加上普通交易與出門查證，即可呈現新手感。兩至三位求助者安排在這些槽位裡，不再外加三份時段負擔。

【建議】第二月最晚賣出日由回流延遲倒算；第六日不能新接一筆必須第三月才能交代的核心任務。長線探索若只是後續伏筆，要明示「尚未返程」，不能假裝完成，也不能是前兩月驗收所必需的獎勵。

## 10 A 方與 B 方如何共同寫世界

GPT 是 A 方，Claude 是 B 方，偉銓是第三個自由創作來源。A、B 可以從不同的可能歷史設計物品，不需要互相提供唯一末日答案；所有已出現在作品中的事實與限制則共同登記。

每件新物件至少記：穩定 ID、正式名與別名、外觀、誰帶回、取得地點與時間、目前持有者、已展示的功能、尚未確認的說法、玩家能看見的文字、與哪些消息相連、哪種條件能進入哪一幕。

物品來源要區分「親眼觀察」「物件上的原文」「NPC 說法」「玩家或許衡推論」。一張記錄聲稱測到不可能的深度，不等於旁白保證儀器正確；一封通知在當天發出，不等於它證明災變因果。

允許的證據衝突，來自不同年代、殘缺、立場、宣傳、誤解、造假與觀測限制。不可接受的衝突，是上一幕已確認燒掉的唯一原件下一幕又完整出現、同一人同時在兩地、同一工具能力隨劇情變動。後者要修，不包裝成世界很神祕。

【建議】先讀本輪故事與相遇場景，再由確實需要的物件衍生卡片，每方最多 2 至 3 件，也可以沒有新物件；不為了湊數先建寶物庫。一次只核准一個相遇場景。先看物件是否有用、有人的痕跡、有值得追問的地方，再看它支持哪些可能解釋。無需向玩家或偉銓主動公布寫手的假說，也不把「模型私下記得」當唯一續寫資料。

偉銓的新靈感先登記為候選，附想保留的核心與尚未解決的衝突。能接上的部分直接納入待寫場景；涉及已發生事實的改動提出最小修訂，不排斥新點子，也不讓既有線索全部被推翻。

結局長線追蹤行動與證據：消息確認／否定、資助哪次探索、NPC 是否回來、物品保留／出售／交研究者或組織、任務與信任的累積。前兩月只建立必要旗標或紀錄，不預製全套結局引擎。後期可用證據網形成不同尾聲，避免最後用「選 AI／外星人／天災」一題代替整局選擇。

## 11 工程施工規格

### 11.2 商機最小資料

每案至少包含：id、可用月份／起迄日、requiredIntelIds、可見來源說明、備貨方案、報價方式、正常來源、目標顧客、到訪窗口、回流延遲、失敗與過期結果、成功後給什麼、要替換哪筆舊收購。

目前 needOk 已有 intel、notIntel、flag、month、資金、持貨、人情等條件。未知 key 可能被忽略，新增條件不可只寫在 YAML 就當引擎會懂；需加解析與拒絕未知欄位的檢查。

推薦狀態流程：available → prepared → customer_due → sold → return_due → settled。declined、expired、failed 是分支終態，必要時可合併中間狀態，但「收到成交款」與「收到探索回流」必須可分辨。

每案持久化：首次發現時間、備貨時間、到訪窗口、回流時間、報價快照、備貨記錄、投入是否扣過、貨款是否收過、回流是否發過、目前狀態與結果收據。成交報價若會變動，先顯示依據；不能讀檔或重繪時重新抽一個價格。

### 11.3 時間與觸發

沿用六個遊戲日的前提下，可用 absDay = (month - 1) × 6 + day；它只代表遊戲的絕對日，不是現實日曆。若日後改每月長度，另做遷移，不能把此式當永遠固定的自然規律。

scanLearn 後檢查新商機；beginDay 推進到期狀態；顧店時從已到訪商機與原有客人中排程；finish 只列尚未完成的商案；nextMonth 保留商機狀態。月底畫面 day 超出本月上限時不應額外跑一次日更新。

舊 S.events 只有事件 ID 與 day，finish 會提前執行月底後事件，nextMonth 又清空。因此新商機用自己的可跨月狀態／到期列表，不把回流直接塞進舊 event.in 或 event.at。除非另立任務逐一驗證全部舊事件，否則不重做原事件引擎。

【建議】O101 到訪窗口內第一次顧店保證遇到該客，取代指定舊收購；回流先採晨間卡，避免再占一格。未來多案同日到訪時，須定固定排序與未服務者的展延／失約規則。不能讓高 prio 舊客把準備多日的新客永遠擠掉，也不能吞掉只出現一天的重要舊客。

### 11.4 金錢與物品只結一次

prepareOpportunity 先完整檢查狀態、錢與已知供應來源，再一次寫入扣款和備貨。點擊兩次、重繪、關閉視窗再載入，不能扣兩次。既有 applyFx 的 take 不足量仍可能繼續執行其他效果，不能直接把它當可靠的整筆投入交易。

sale 與 settle 分別檢查狀態和收據。備貨採專用記錄，避免同時出現在普通庫存讓散客賣掉，或被資產計算重複計入。若期限後轉回普通貨，轉入與清除備貨記錄也必須一次完成。

新商案不能自動消耗狐尾燈、證物、受託品或未知的玩家存貨。若未來開放使用現有庫存，另做明確規格、保留量和選批邏輯，不混進第一個切片。

### 11.5 存檔與 ID

現行 v1 與 fangshi-p1-v1 存檔只補缺少的頂層預設值。新增巢狀商機資料，要檢查型別、缺欄位與狀態，避免舊存檔一載入就報錯。若提升 save version，讀取入口亦須接受並遷移舊版；不能改版本號卻維持 saved.v === 1 的唯一入口。

顯示名可改，item、NPC、deal、intel、event、flag 的穩定 ID 盡量保留。要換 ID 時，列 alias／遷移表，涵蓋庫存、done、intel、isold、人物記憶、圖示與 YAML from/need/fx 交叉引用。不能只全域文字替換。

【建議】技術可讀與故事連貫分開驗收。舊存檔不能無聲刪掉，但也不能宣稱古風世界的所有已發生事件已自動符合新故事。保留原版檔；新故事的主要試玩使用新開局。若只做顯示名改寫可相容續玩，若涉及物件功能或支線答案改變，先提出遷移或分版本方案再採用。

### 11.6 必要的基線清理

- d19.special 存在重複 seal 鍵；目前解析後採「還刀」。移除被覆蓋的舊鍵以維持既有結果，並加入 YAML 重複鍵檢查。
- 燈的唯一性檢查以正常可達路徑為準，另防新路由繞過完成記錄。不要把已存在的正常限制誤報成已修復漏洞。
- 重寫物品文時檢查絕對句，例如「從不漲價」是否與晨報的實際調價矛盾。可以改成一般人的市場印象，不能同時保留兩個客觀版本。
- 現有「前世記憶可見」標籤需移除或有明確批准的新解釋，不能由此擅立許衡穿越設定。
- harness.py 的舊固定輸出路徑需可設定；每次驗證清楚區分靜態檢查、模擬與人工試玩。

### 13.3 放行前的必要檢查

| 類型 | 必測情境 | 通過標準 |
| --- | --- | --- |
| 文本 | S01、每幕後半段、多人對話、先前關係不同的分支 | 不靠失憶補解說；動機可追；說話者清楚；不違反已知狀態 |
| 世界 | 新貨、派出所、舊科技、日期碎片 | 物品與制度符合新世界；推測不冒充事實；無唯一末日答案 |
| 線頭 | 缺一則、全取得、已過期、兩則只是同源轉述 | 不偷看 hidden truth；卡片依玩家可得資訊出現，同源不充當獨立佐證 |
| 資源 | 資金不足、連點備貨、成交連點、過期轉貨 | 不負扣、不重扣、不重發貨款、不複製貨物 |
| 時間 | 月末備貨、次月到訪／回流、同日多個到期案 | 不提前或丟失；顧客排序明確；規費與舊事件仍正常 |
| 存檔 | 舊版檔與每個商機狀態存讀；重複 tick／settle | 狀態連續，金錢與獎勵各一次；資料錯誤有可理解處理 |
| 選擇 | 拒絕、先不做、查證、失約、猜錯、成功 | 後果能由資訊理解，普通經營仍可持續 |
| 唯一性 | 狐尾燈／受託品進出庫、跨月與新路由 | 不被商機採購／消耗，不重領、不重複計價 |
| 視覺 | 402×874、深淺模式、長中文名、圖示與鎖定選項 | 無遮擋、缺圖、答案表情提前洩露；操作狀態清楚 |
| 結束 | 第二月最後可玩日與未回流案件 | 必要內容能回收；後續伏筆明示未完，不假結算 |

數值驗收建議：先選相同種子的普通經營、合理使用商機、輕信未查證三種策略，各跑 20 個固定種子，記錄總收入、商案淨貢獻、規費缺口、完成案數、失約原因與占用時段。有具體不穩定問題才擴大。合理策略只能用畫面上能取得的資訊，不直接讀 truth／verdict。

目標是讓合理用情報的策略更能穩定完成經營目標，且收益來源有可追溯理由；具體百分比等第一個循環可玩後再訂。模擬只驗證可達性與數值，偉銓實際玩一條路線才能驗證「像在當掌櫃」與「想等人回來」。

美術先整理現有墨線圖示與表情規格。新寶物可改輪廓和材質感，維持線寬、底色、對比、留白與圖示尺寸。動畫安排在核心循環和文字已穩定之後，先做不干擾閱讀的短回饋，不同時重做整個視覺系統。
